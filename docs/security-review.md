## Findings and changes

The legacy `--framework-spike` development route was reachable in release source. It opens an inert feasibility gallery, not the vault, and no credential bypass was found. The route is now compiled only with debug assertions; release configuration checks pass. Actual packaged-binary inspection belongs to Task23.

Three project-owned plaintext conversions could grow a buffer before its zeroizing owner was dropped: filtered Base32 normalization, UTF-16 clipboard conversion and recovery-file reading. They now reserve bounded storage first. Recovery-file reading uses a fixed initialized MAX+1 buffer and reads only into its remaining slice, avoiding any `read_to_end` EOF-allocation assumption. This reduces avoidable abandoned allocations; it does not erase framework, dependency, allocator, OS, clipboard or compiler copies. Existing input rules, ownership checks and limits are unchanged.

Local and portable writers already had partial-write and pre-rename fault tests. Task20 adds an explicit test-only writer that writes a bounded ciphertext prefix through the real file, then returns `ErrorKind::StorageFull`. Existing transaction/overwrite tests verify unchanged committed memory/files and cleanup. This does not fill a real disk or demonstrate physical power-loss durability. A subprocess test now exercises the production panic-hook function, attests that its child reached the panic point, and verifies exit 101 without its disposable payload in stdout/stderr. It does not control Windows crash dumps.

No confirmed unresolved material encryption or data-loss defect was identified in the focused source scope below. This bounded source assessment was independently reviewed; unknown interactive clipboard behavior and mandatory native/offline gates are not accepted as passed.

## Runtime and artifact probe

The disposable CLI example [security_audit.rs](../examples/security_audit.rs) decodes a generated published-vector QR in memory, explicitly commits to an isolated encrypted vault, adds used recovery state/folder links, exports an encrypted backup, restores into an independently created vault and verifies the RFC6238 code and used state after encrypted reopen. Its recursive scan checks only its own temporary tree for service/account/folder/recovery/passphrase/seed/raw-URI markers; the session lock is checked as empty. It prints only a fixed result line. No production/default/reference vault, real credential, screenshot or user clipboard is used.

The first own-PID `netstat -ano` observation produced 66 successful samples with 0 TCP / 0 UDP entries; final-source repetition produced 61 successful samples with the same counts and passed the core/artifact assertions. No other process's endpoints were printed or retained. Adapters stayed enabled. Sampling can miss transient connections and does not prove disconnected-machine behavior. Source/dependency inspection found no runtime HTTP/socket/icon-fetch path; `reqwest` and `webbrowser` are absent from the locked graph. The required native, network-disabled clean-install journey is still unverified.

## Dependencies and licenses

`cargo-audit 0.22.2` checked 381 locked dependencies against 1490 RustSec advisories, database commit `af7b3ec33460b8e2de8d422e16d628518891a519`, updated 12 November 2026. It found 0 known vulnerabilities with no ignored advisories. Three informational unmaintained notices remain in the all-platform lockfile: [zvariant RUSTSEC-2026-0370](https://rustsec.org/advisories/RUSTSEC-2026-0370.html), [zbus_names RUSTSEC-2026-0371](https://rustsec.org/advisories/RUSTSEC-2026-0371.html), [zvariant_derive RUSTSEC-2026-0372](https://rustsec.org/advisories/RUSTSEC-2026-0372.html). The actual Windows normal dependency tree excludes their Unix AT-SPI/zbus chain; they were not hidden by an ignore list. Future non-Windows work must revisit that upstream migration. This time-specific advisory result is not proof of absence of vulnerabilities. [Machine-readable audit summary](qa/task20/dependency-audit.json).

The filtered Windows normal/build graph has 185 packages including Authenticator, each declaring license metadata. [Inventory](qa/task20/windows-dependencies.json). The review retained AND obligations, OR alternatives and two legacy `MIT/Apache-2.0` metadata spellings rather than treating all declarations as one license. `dpi` declares Apache-2.0 AND MIT; `self_cell` permits Apache-2.0 as an alternative to GPL; `epaint_default_fonts` additionally declares OFL-1.1 and Ubuntu-font-1.0. Its actual font notice files and the project's Noto OFL file are present. Task23 must carry the relevant license/notice texts into the package, including font notices; this inventory alone is not a distribution-compliance certificate. Cargo's [manifest documentation](https://doc.rust-lang.org/cargo/reference/manifest.html#the-license-and-license-file-fields) defines the declaration semantics.

A targeted current-tree key/token-pattern scan returned no matches and no tracked `.vault/.authpbk/.key/.pem/.pfx/.dmp/.exe/.dll` paths. Source fixtures inspected are published or generated disposable values. Existing sanitized UI evidence was not re-certified pixel by pixel in this audit, and a regex scan cannot establish that every possible secret pattern is absent. No real user data was accessed to test redaction.

## Open gates and residual limits

- Distinct Task20 source review and hosted full checks passed (CI43397135687 on4e0f715; see qa/task20/hosted-follow-up.md). Independent25 focused cases and core recovery/sentinel probe passed; no full native or disconnected-machine acceptance is inferred.
- Native full journeys, physical DPI/Narrator/high contrast, actual OS lock/suspend/logon, disconnected-machine operation and packaged clean-profile recovery remain open. Current Task10 [clipboard correction and native evidence](qa/task10/clipboard-availability-fix.md) and [independent re-review](qa/task10/availability-independent-review.md) establish scoped Copy/expiry/later-copy/Lock/exit behavior after a real availability-failure repair; recovery-code UI and every clipboard environment are not inferred from that evidence.
- A compromised unlocked endpoint, administrator/process memory access, clipboard history/observers, pagefile/hibernation/OS dumps and prior exported backups remain outside complete protection. Zeroizing owners reduce lifetime, not all copies.
- Atomic logical replacement is not a promise of physical power-loss durability or secure SSD/filesystem/memory erasure. Existing backups are neither revoked nor rewritten by Trash deletion. Malicious concurrent same-user filesystem/registry manipulation has documented race limits.
- Bounded crypto/decoder/OS work is cooperative. Cancellation that wins admission prevents a write; a complete action already admitted may finish, with late unlocked adoption blocked. A stalled OS call cannot be forcibly erased by the app.

Use disposable data until required acceptance is closed and keep independent service recovery methods. No reference-app private-format compatibility, external audit or ranking/security certification is asserted.
